What is Python?

Python is a general-purpose programming language created by Guido van Rossum, first released in 1991. "General-purpose" means it isn't built for one job: the same language runs websites, automates files, controls robots and — our focus — analyses data. It is famous for being versatile, flexible and easy to learn, and it has one of the biggest communities on GitHub, Stack Overflow and Meetup, which means almost any problem you hit has already been asked and answered.

Why is Python slow?

First, a mindset: there are two kinds of time.

time <engineer>

Your time

How fast you can write the code and how fast you can change it. Python is excellent here.

time <CPU>

The computer's time

How fast the finished program runs. Languages like C, C++ or Rust beat Python here.

Worth knowing

An example: two developers build the same app with the same skills, one in Python and one in a compiled language. The Python developer finishes and delivers first. The other takes longer to write it, but their finished app runs faster.

A fair summary: "There are better languages than Python for making things work quickly. Python is a language for making things work, quickly." For data science that's usually the right deal — and when speed matters, we use the tricks in 1.3 and libraries written in C (1.5). Three design choices cost Python its speed:

1 · Python is interpreted

A compiled language (C) is translated once, ahead of time, into machine code the CPU runs directly. Python works in two steps:

  1. Your source code is first compiled into bytecode — a simpler, lower-level list of instructions (saved as .pyc files in __pycache__). This is the "compile first" step, sometimes called ahead-of-time compilation.
  2. The Python Virtual Machine (PVM) then reads that bytecode one instruction at a time and carries each one out. That reading-and-dispatching is the "interpreting", and each of your instructions costs many machine instructions.

You can see the bytecode with the built-in dis (disassembler) module:

import dis

def add(a, b):
    return a + b

dis.dis(add)
  3           0 RESUME                   0

  4           2 LOAD_FAST                0 (a)
              4 LOAD_FAST                1 (b)
              6 BINARY_OP                0 (+)
             10 RETURN_VALUE

Each line is one bytecode instruction: LOAD_FAST fetches a local variable, BINARY_OP does the +, RETURN_VALUE returns. More instructions ≈ more work for the interpreter.
Worth knowing

Compiler vs interpreter: a compiler translates the whole program into machine code in one go. An interpreter works one statement at a time: translate a statement, run it, then come back for the next one. That back-and-forth costs time, and it's one of the main reasons Python is slower.

2 · Python is dynamically typed

In C you declare int a = 0; and a can only ever hold an integer, so the compiler knows exactly how to add it. In Python a variable is just a name stuck on an object; the name has no type — the object does — and the same name can later point to an object of a completely different type. So every time Python executes a + b it must first check what a and b are right now, then pick the right "+". Flexible for you, extra work for the CPU.

Worth knowing

Step by step: with a = 0, Python only learns at run time that the value is an integer, and reserves space for one. Later, a = "…a long string…" no longer fits, so Python has to find a new, bigger place in memory. This can happen many times while the program runs. In C the type is fixed before the program starts, so the memory is reserved once.

3 · Python is single-threaded (the GIL)

A modern CPU has several cores. A program can split work into threads to use them at the same time. Standard Python (CPython) has a Global Interpreter Lock (GIL): a single lock that a thread must hold to run Python bytecode. Only one thread can hold it at a time — so even with many threads, only one is executing Python code at any moment. Pure-Python number crunching therefore can't use more than one core.

see itThree threads, one lock
Good to know
  • Threads do help when the work is waiting on input/output (network, disk): a thread releases the GIL while it waits.
  • For CPU-heavy work, Python uses multiprocessing (several processes, each with its own interpreter and GIL) — or libraries like NumPy that do the heavy lifting in C outside the GIL.
  • Python 3.13 (2024) added an experimental "free-threaded" build without the GIL; it isn't the default yet.

Making Python faster: the habits

The key sentence: improving the performance of a Python program is the programmer's problem. Python won't optimise for you, so these habits matter. First, measure: the timeit module runs a piece of code many times and tells you how long it took.

import timeit

seconds = timeit.timeit("sum(range(1000))", number=10000)
print(f"10,000 runs took {seconds:.3f} s")
10,000 runs took 1.222 s

Use the latest Python release

  
Each new version gets faster for free. Python 3.11, for example, was about 25% faster than 3.10 on average, because the interpreter learned to specialise bytecode for the types it actually sees.


  
Keep your code simple and readable

  
    
    
  • Meaningful names for variables and functions: total_price, not tp.
    • 
    
  • Whitespace and indentation — in Python indentation is part of the syntax.
    • 
    
  • Comments that explain why, not what.
    • 
    
  • Naming conventions (PEP 8): snake_case for variables and functions, CamelCase for class names.
    • 
    
  • Small, focused functions — each does one thing. It also helps you spot and delete dead code (code that never runs).
    • 
  

  
class BankAccount:                 # CamelCase for classes
    def __init__(self, owner_name):  # snake_case for functions and variables
        self.owner_name = owner_name
        self.balance = 0

    def deposit(self, amount):       # small and focused: does one thing
        self.balance += amount

account = BankAccount("Omar")
account.deposit(500)
account.balance

  
500


  
Avoid global variables

  
Inside a function, Python finds local variables by position in a fast array, but global variables by looking up a dictionary — slower, every single time. The lab's "local vs global" race shows the difference.

  
Worth knowing
A typical measurement: build a string 50 times inside a function and time it with timeit. It took about 1.68 s using a global variable vs 1.59 s using a local one. That's a small gap, but it grows with the number of operations.


  
Use multiple assignment

  
x, y, z = 1, 2, 3
print(x, y, z)

x, y = y, x          # swap without a temporary variable
print(x, y)

Use list comprehensions

  
A list comprehension builds a list in one expression. It's shorter and faster than a for loop with .append(), because the looping happens inside optimised interpreter code.

  
squares = []
for n in range(10):
    squares.append(n * n)
print(squares)

squares = [n * n for n in range(10)]
print(squares)

even_squares = [n * n for n in range(10) if n % 2 == 0]
print(even_squares)

  
[0, 1, 4, 9, 16, 25, 36, 49, 64, 81]
[0, 1, 4, 9, 16, 25, 36, 49, 64, 81]
[0, 4, 16, 36, 64]

  
Worth knowing
A typical measurement: squaring every number up to 500 took about 20 seconds with a for loop and 12–13 with a list comprehension (roughly 7 seconds faster). Small differences matter in real-time systems such as medical or military applications, where even 0.001 s can count. Loops in general, and for loops especially, are where programs spend most of their time, so they're the first place to optimise.


  
Optimise your loops

  
    
    
  • "Use 1 for infinite loops" — while 1: instead of while True:. This was a real speed-up in Python 2, where True was a variable that had to be looked up. In Python 3 both compile to the same bytecode — check it in the bytecode viewer above.
    • 
    
  • Use sets and union to combine or de-duplicate collections instead of nested loops.
    • 
    
  • "while instead of for" — an often-repeated tip. In modern CPython a for … in range() loop is usually faster than a while loop with a manual counter, because the counting happens in C. Race them in the Speed Lab ("for vs while") and see for yourself.
    • 
  

  
group_a = {"Ahmed", "Salma", "Omar"}
group_b = {"Omar", "Mona"}
print(group_a | group_b)      # union
print(group_a & group_b)      # intersection
print(set([1, 1, 2, 3, 3]))   # remove duplicates

  
{'Salma', 'Ahmed', 'Omar', 'Mona'}
{'Omar'}
{1, 2, 3}

  
Worth knowing
An example: find the items two lists have in common. Using nested loops (compare every item of the first list with every item of the second) vs converting both to sets and taking the intersection set_a & set_b. The set version took about half the time.


  
Optimise your conditions

  
    
    
  • Exit early: return as soon as you know the answer, so the rest of the code doesn't run.
    • 
    
  • Don't compare with True: write if is_valid:, not if is_valid == True:.
    • 
  

  
def has_negative(numbers):
    for n in numbers:
        if n < 0:
            return True        # stop at the first one, don't check the rest
    return False

is_valid = has_negative([5, 3, -1, 8, 9])
if is_valid:                   # not: if is_valid == True
    print("found a negative number")

  
found a negative number


  
Use join to concatenate strings

  
Strings are immutable: s = s + "x" builds a brand-new string each time, copying everything so far. "".join(pieces) builds the result once.

  
words = ["Python", "is", "fun"]
print(" ".join(words))
print(", ".join(str(n) for n in range(5)))

  
Python is fun
0, 1, 2, 3, 4


  
Be lazy with your imports

  
    
    
  • from math import sqrt imports just what you need and lets you call sqrt(x) directly.
    • 
    
  • from math import * dumps every name from math into your program. You'll see it in tutorials, but PEP 8 recommends avoiding it: you can't tell where a name came from, and it can silently overwrite your own variables.
    • 
    
  • "Lazy" also means importing a heavy library only inside the function that needs it, so the program starts faster.
    • 
  


  
Avoid repeated dot operations

  
Every . is a lookup at run time. Inside a hot loop, math.sqrt(x) looks up math, then sqrt on it, every iteration. Saving it in a local name first (sqrt = math.sqrt, or from math import sqrt) skips that work — race it in the lab ("dot lookups").


  
Use libraries and built-in functions — don't reinvent the wheel

  
Worth knowing
“If you need a neural network, don't write one from scratch.” One of Python's biggest strengths is its huge community and number of libraries. Before building something, search for it — it has most likely been implemented already, and you only need to import it.

  
numbers = [4, 8, 15, 16, 23, 42]

total = 0
for n in numbers:          # reinventing the wheel
    total += n
print(total)

print(sum(numbers), max(numbers), sorted(numbers, reverse=True))

A taste of profiling: cProfile runs your code and reports how much time each function took — so you optimise the part that matters instead of guessing.

  
import cProfile, pstats

def slow_part():
    return sum(i * i for i in range(300_000))

def fast_part():
    return sum(range(1000))

def program():
    slow_part()
    fast_part()

profiler = cProfile.Profile()
profiler.enable()
program()
profiler.disable()
pstats.Stats(profiler).sort_stats("cumulative").print_stats(5)

Why NumPy is fast: a NumPy array stores raw numbers side by side in memory and runs whole-array operations in C — vectorisation — instead of looping over Python objects one by one.

  
import timeit
import numpy as np

values = list(range(100_000))
array = np.arange(100_000)

t_loop = timeit.timeit(lambda: [v * 2 for v in values], number=20)
t_numpy = timeit.timeit(lambda: array * 2, number=20)
print(f"Python list: {t_loop:.4f} s")
print(f"NumPy array: {t_numpy:.4f} s  ->  about {t_loop / t_numpy:.0f}x faster")

  
Python list: 0.4982 s
NumPy array: 0.0087 s  ->  about 57x faster

  
There are two more ways to go faster when a single core isn't enough: multiprocessing / parallel programming (several processes at once, side-stepping the GIL) and GPU acceleration (thousands of small cores, used by deep-learning libraries).

Big data: Hadoop and Spark

  
When data is too big for one computer, it is split across many. Python talks to the two classic systems:

  

    
Apache Hadoop
Stores huge files across many machines (HDFS) and processes them with MapReduce: each machine works on its own piece (map), then the partial results are combined (reduce). Reads and writes to disk between steps.

    
Apache Spark
The same idea, but keeps data in memory between steps, so it is much faster, especially for repeated computations like machine learning. Python uses it through PySpark.

Chapter 1 quiz

    
What happens to your .py file before the Python Virtual Machine runs it?

      

      
Source → bytecode (dis shows it) → interpreted by the PVM. That interpretation step is a big part of why Python is slower than C.

    
Why does dynamic typing slow Python down?

      

      
A name can point to any type, so before a + b Python must look at what a and b currently are.

    
What does the GIL do?

      

      
Global Interpreter Lock: one thread at a time. For CPU-heavy work use multiprocessing or C-based libraries like NumPy.

    
Which is the best way to build a long string from many pieces?

      

      
Strings are immutable, so + in a loop copies the growing string each time; join builds it once.

    
You need to check, thousands of times, whether an ID is in a collection of 100,000 IDs. Which structure?

      

      
Membership in a set (or dict keys) is near-instant whatever its size; a list has to be scanned from the start.

    
What's the naming convention for a class?

      

      
PEP 8: CamelCase for classes, snake_case for variables and functions. Python doesn't enforce it, but everyone reads code faster when it's followed.

    
How does Spark differ from Hadoop MapReduce?

      

      
Hadoop writes intermediate results to disk; Spark keeps them in RAM. PySpark is Spark's Python interface.

  • Too big for one machine → Hadoop (MapReduce on disk) or Spark (in memory, via PySpark).
