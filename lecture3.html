3.1

Metaprogramming, and "everything is an object"

Metaprogramming is writing programs that create or change other programs. In Python it works because everything — numbers, functions, classes — is an object that has a type and can be passed around. The notebook starts by asking for the type of everything, then the type of that type:

In the lecture

The lecturer explained “meta” through metadata: a table's rows and columns are data, and the description of that data (what each column is, its type) is data about data. Likewise, ordinary programming writes a program that does a task, while metaprogramming writes a program that can generate another program or change how one works. Decorators and metaclasses are Python's two tools for this.

3.3

Decorators

A decorator is a function that takes a function and returns a new one that changes its behaviour without modifying its code. It's built from exactly the three facts above: the decorator receives a function (③), defines a wrapper inside (①) and returns it (②).

def make_pretty(fun):
    def inner():
        print("I got decorated")
        fun()
    return inner


def ordinary():
    print("I am ordinary function")
decorated_fun = make_pretty(ordinary)
decorated_fun()
I got decorated
I am ordinary function

Writing ordinary = make_pretty(ordinary) every time is clumsy, so Python gives a shortcut: put @make_pretty on the line above the definition.

Why use a decorator? The lecturer's answer: when you want a function to do a bit more — check its data before it runs, or format its output — without touching its implementation. You write the extra behaviour once as a decorator and put @name on any function that needs it, instead of editing every function.

Decorating functions that take arguments

The wrapper must accept the same arguments as the function it wraps. This one checks the arguments before the division happens:

def smart_divide(fun):
    def inner(a, b):
        if b == 0:
            print("Zero Division Error")
            return
        else:
            return fun(a, b)
    return inner

@smart_divide
def divide(a, b):
    print(a / b)

import time, functools

def timer(fun):
    @functools.wraps(fun)              # keep the original name and docstring
    def inner(*args, **kwargs):        # accept whatever the function accepts
        start = time.perf_counter()
        result = fun(*args, **kwargs)
        print(f"{fun.__name__} took {time.perf_counter() - start:.4f} s")
        return result
    return inner

The order rule

Decorators are applied bottom-up (the one nearest the function wraps it first), so the top one ends up as the outermost layer and prints first and last. @star @percent means printer = star(percent(printer)).

In the lecture

How she traced @star over @percent: the call enters star's inner function, which prints its 20 stars and then calls the next layer. percent's inner prints its 20 % signs and calls the original printer. Then each layer finishes in reverse: the % line, then the star line. Swap the decorators and the % lines end up on the outside.

__eq__: what does "equal" mean?

  
p4 = Person("Salma", 22)

  
In the lecture
Without __eq__, == asks whether both names point to the same object in the same place in memory, not whether their values match. That's why two people with identical names and ages compare as False until you define what equality means.

  
p3 == p4

  
False

  
By default == on objects asks "are these the same object in memory?" — and p3 and p4 are two separate objects. __eq__ lets you decide what equal means for your class:

  
class Person:
    counter = 0
    def __init__(self, name, age):
        self.name = name
        self.age = age
        Person.counter += 1

    def __str__(self):
        return f'{self.name}, {self.age}'

    def __repr__(self):
        return f'Person({self.name}, {self.age})'

    def __eq__(self, other):
        return self.age == other.age 

  
p3 = Person("Salma", 22)

  
p4 = Person("Salma", 22)

Read the rule carefully
This __eq__ compares age only, so Person("Salma", 22) == Person("Omar", 22) is True even though they're different people. You choose what "equal" means — choose deliberately (e.g. self.name == other.name and self.age == other.age).

3.7
Metaclasses

  
From the slide, three ways of saying the same thing: a metaclass is a class that defines the behaviour of classes; a class whose instances are classes; a class that creates other classes. type is the default one. You write your own by inheriting from type, and you use one when you want to change or record classes automatically when they are created.

  
The lecture's example keeps a registry of every class made with the metaclass Animal:

  
class Animal(type):
    registery = {}

    def __new__(cls, name, bases, dct):
        new_class = super().__new__(cls, name, bases, dct)
        if name not in Animal.registery:
            Animal.registery[name] = new_class
        return new_class

    @classmethod
    def list_animals(cls):
        print(cls.registery)

  
    
    
  • Animal.__new__ runs every time a class (not an object!) is created with metaclass=Animal. Its arguments are exactly the three that type(name, bases, dict) takes.
    • 
    
  • super().__new__(…) lets type build the class as usual; then the metaclass records it.
    • 
    
  • @classmethod means list_animals receives the class (cls) instead of an instance — another decorator from this lecture.
    • 
  

  
In the lecture
The use case from class: a base class such as Person gets many subclasses (Student, Employee, …). A metaclass can keep a registry of every class created that way, automatically, without adding any code to the subclasses themselves.

  
class Dog(metaclass=Animal):
    pass

class Cat(metaclass=Animal):
    pass

    pass

3.8
Generators

  
An iterator is an object you can loop over one item at a time — lists, tuples, dictionaries and sets all give you one. A generator is a function that returns an iterator using the yield keyword: it looks like a normal function, but where a normal function returns one value and is finished, a generator yields a value, pauses, and continues from the same spot the next time you ask.

    print(i, end=" ")

Why bother? Memory

  
The slide's last point: a generator doesn't produce all its values at once, which can mean better performance. A list holds every item in memory; a generator holds only its current state.

  
import sys

squares_list = [i * i for i in range(1_000_000)]   # square brackets: builds everything now
squares_gen  = (i * i for i in range(1_000_000))   # round brackets: a generator expression

print(f"list:      {sys.getsizeof(squares_list):>10,} bytes")
print(f"generator: {sys.getsizeof(squares_gen):>10,} bytes")
print(sum(squares_gen) == sum(squares_list))       # same values in the end

  
list:       4,224,364 bytes
generator:        104 bytes
True

  
import itertools

def count_up(start):
    while True:              # never ends — fine, values are only made on request
        yield start
        start += 1

print(list(itertools.islice(count_up(100), 5)))

  
[100, 101, 102, 103, 104]

  
One pass only
A generator is used up once it has been looped over. In the cell above, sum(squares_gen) consumed it; a second sum(squares_gen) would give 0. Call the generator function again (or rebuild the expression) to start over.

Summary

  
    
    
  • Metaprogramming: code that makes or changes code. Possible because everything — even functions and classes — is an object; type(type(anything)) is type.
    • 
    
  • Functions can be nested, returned and passed. An inner function that remembers outer variables is a closure.
    • 
    
  • A decorator wraps a function to change its behaviour without editing it. @d = f = d(f). Stacked decorators apply bottom-up; the top one is outermost.
    • 
    
  • __str__ → readable (print); __repr__ → unambiguous (repr, Out[], lists); __eq__ → what == means (default: same object).
    • 
    
  • Object creation = __new__ (create, gets cls) then __init__ (initialise, gets self).
    • 
    
  • type(name, bases, dict) builds a class at run time. A metaclass (inherits from type) controls class creation, e.g. auto-registering classes.
    • 
    
  • A generator uses yield to give values one at a time, pausing in between; next() resumes it, StopIteration ends it. Saves memory.
    •
