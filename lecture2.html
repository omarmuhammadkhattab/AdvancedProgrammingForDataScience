2.1

What is object-oriented programming?

Object-oriented programming (OOP) structures a program by bundling related properties (data) and behaviours (functions) into individual objects. Two examples:

class Person

Properties: name, age, address

Behaviours: walking, talking, breathing, running

class Email

Properties: recipients, subject, body

Behaviours: adding attachments, sending

WordMeaningAnalogy
classa special data type that defines how to build a certain kind of objectthe blueprint of a house
instance / objectan object created from the class, following its definitionan actual house built from the blueprint
attributedata stored in an object (name, age)the colour of this particular house
methoda function defined inside a class"open the door" — something every house can do
In plain English

You already use objects all the time: "hello".upper() calls the upper method of a str object, and [1, 2].append(3) calls a method of a list object. A class lets you invent your own types like that.

2.2

Defining a class and creating objects

Worth knowing

Another way to see it: Python already gives you data types such as int (whole numbers), float (decimals) and str (text). A class lets you create a new data type when none of those fits, such as Student or Book. A Book class says every book has a title, an author, a price and a publication year. One instance is a particular book, for example “Introduction to Programming”, published in 2010.

Methods describe behaviour: a class for a robot or a self-driving car could have methods to turn left or right, or to brake under certain conditions.

class Person:
    def __init__(self, name, age, address):
        self.name = name
        self.age = age
        self.address = address
  • class Person: starts the class. Everything indented below belongs to it.
  • __init__ is the constructor: Python calls it automatically every time a new Person is created, to set up the new object's data.
  • self is the object being created. self.name = name stores the value of the argument name as an attribute on this object.

To create an object, call the class like a function. The arguments go to __init__:

p1 = Person("Ahmed", 25, "Giza")
p1
<__main__.Person object at 0xdef698>

Printing the object itself isn't very helpful yet: it shows the class and its memory address (where it lives). In chapter 3 we'll teach it to print itself nicely with __str__ and __repr__. Its attributes are reached with a dot:

p1.name
'Ahmed'
p1.age
25
type(p1)
__main__.Person
x = 100
type(x)
int

type(p1) is Person, just like type(100) is int: our class is a type, exactly as real as the built-in ones.

2.3

__init__, default values and self

Like any function, __init__ can give arguments default values, which makes them optional when creating an object:

class Person:
    def __init__(self, name, age=25, address="Giza"):
        self.name = name
        self.age = age
        self.address = address
p2 = Person("Salma")
p2.age
25
p2.address
'Giza'
p3 = Person("Mohmed", 23)
p3.address
'Giza'
Worth knowing

Give a default only where one makes sense. A default address like Giza is fine, and so is a default player name in a game. But a name on an official record should not have a default: leaving it out should raise an error so the user has to enter it. Python also doesn't let you declare the argument's type (number or string?). Checking the input is done separately, with error handling, later on.

About self

  • The first parameter of every method is a reference to the current instance. By convention it's called self (it's like this in Java or C++).
  • In __init__, self is the object being created; in other methods, it's the object whose method was called.
  • You write self when defining a method, but you don't pass it when calling it: p1.display() really runs Person.display(p1).
Worth knowing

self is the same idea as this in Java or C++. It isn't a keyword: any name for the first parameter would work, but everyone agrees to call it self, so use that to keep your code readable.

class Greeter:
    def __init__(self, name):
        self.name = name
    def hello(self, other):
        return f"{self.name} says hi to {other}"

g = Greeter("Salma")
print(g.hello("Omar"))
print(Greeter.hello(g, "Omar"))   # exactly what Python does behind the scenes
Salma says hi to Omar
Salma says hi to Omar

No need to "free" objects

When you're done with an object you don't delete it yourself: Python has automatic garbage collection. It counts how many names point at each object; when none are left, the memory is freed. (You'll often read that Python has no destructor; strictly there is a __del__ method, but you almost never need it and you can't rely on exactly when it runs.)

Worth knowing

Languages like C++ have a constructor that builds the object and a destructor that removes it from memory. Python doesn't need the destructor. It keeps a reference count for each object: every time your code uses it the count goes up, and every time a use ends it goes down. When nothing refers to the object any more, it's deleted from memory automatically.

import sys

a = Person("Mona")
b = a                       # a second name for the same object
print(sys.getrefcount(a))   # references (the count includes a temporary one used by getrefcount)
del a                       # removes the NAME a, not the object
print(b.name)               # the object is still alive through b
3
Mona
2.4

Instance attributes vs class attributes

data / instance attribute

Owned by one particular object; each instance has its own value. Created in __init__ with self.x = …. The most common kind.

class attribute

Owned by the class as a whole and shared by all instances ("static" variables in other languages). Defined inside the class but outside any method. Classic use: counting how many instances were made.

Worth knowing

An analogy: a class attribute is like a shared file on Google Drive. Everyone works on the same file, so when one person edits it, everybody sees the change. A data attribute is like each person's own copy on their laptop: your edits change only your copy. The classic use of a class attribute is a counter of how many students, books or people have been created.

class Person:
    number_of_person = 0
    def __init__(self, name, age=25, address="Giza"):
        self.name = name
        self.age = age
        self.address = address
        Person.number_of_person += 1
p1 = Person("Ahmed")
p1.number_of_person
1
p2 = Person("Mohmed")
p1.number_of_person
2
p2.number_of_person
2
Person.number_of_person
2

Notice Person.number_of_person += 1 in __init__: it updates the attribute on the class. That's essential, as the lab below shows.

class My_Counter:
    overall_total = 0
    def __init__(self):
        self.my_total = 0
    def increment(self):
        self.my_total += 1
        My_Counter.overall_total += 1
a = My_Counter()
b = My_Counter()
a.increment()
b.increment()
b.increment()
b.increment()
My_Counter.overall_total
4
a.my_total
1
b.my_total
3
print(vars(a))    # a stores only its own my_total
print(vars(b))
print(My_Counter.__dict__["overall_total"])   # overall_total is stored once, on the class
{'my_total': 1}
{'my_total': 3}

Worth knowing

You can see this with id(), which gives the memory address: a.overall_total and b.overall_total have the same address (one shared variable), while a.my_total and b.my_total live at different addresses (one copy per object).

Common trap

Reading obj.overall_total finds the class attribute. But assigning obj.overall_total = 100 does not change the class attribute — it creates a new instance attribute on that one object that hides ("shadows") the shared one. To change the shared value, always write ClassName.attribute = ….

2.5

Accessing attributes and methods by name

Asking for an attribute that doesn't exist raises an AttributeError:

p1.course
AttributeError: 'Person' object has no attribute 'course'

Sometimes the name of the attribute you want is only known at run time — it comes from user input, a file, or a column name in a dataset. For that Python has built-in functions that take the name as a string:

hasattr(p1, "email")
False
hasattr(p1, "name")
True
getattr(p1, "name")
'Ahmed'
getattr(p2, "age")
25
getattr(a, "increment")()
print(getattr(p1, "email", "no email"))   # third argument = value if missing
setattr(p1, "email", "ahmed@mail.com")     # create or change an attribute by name
print(p1.email)
for field in ["name", "age", "email"]:      # loop over attribute names
    print(field, "=", getattr(p1, field))
no email
ahmed@mail.com
name = Ahmed
age = 25
email = ahmed@mail.com

A common question: can a method create a new attribute? Yes. Any self.something = … inside a method adds it to the object, just like in __init__:

class Person:
    def __init__(self, name):
        self.name = name
    def set_course(self, course):
        self.course = course          # a new attribute, created when the method runs
        temp = course.upper()         # no self: a local variable, gone when the method ends

b1 = Person("Ahmed")
print(hasattr(b1, "course"))
b1.set_course("Statistics")
print(hasattr(b1, "course"), b1.course)
print(hasattr(b1, "temp"))
False
True Statistics
False
Worth knowing

The difference to remember: a variable inside a method without self is an ordinary local variable that disappears when the method ends. An attribute set with self. belongs to the object and stays until the object itself is removed from memory.

2.6

Inheritance

Inheritance lets one class take on the properties and methods of another. The class that inherits is the child (derived) class; the one it inherits from is the parent (base) class. Its benefits: it models real-world "is-a" relationships (a teacher is a person), it reuses code, and it lets you add features to a class without modifying it.

Worth knowing

More examples: a Computer class whose children are laptop, desktop, mobile and tablet. A Person (name, national ID) whose children include Employee (adds a salary) and Student (adds a grade and a school). The child gets everything from the parent and adds its own features, without touching the parent's code.

Inheritance can also be multi-level (grandparent → parent → child) or multiple (one class inheriting from several). These notes cover only the single-level case; search “multilevel inheritance” and “multiple inheritance” if you want to go further.

class Person:
    number_of_person = 0
    def __init__(self, name, age=25, address="Giza"):
        self.name = name
        self.age = age
        self.address = address
        Person.number_of_person += 1
    def display(self):
        print(self.name)
class Teacher(Person):
    def __init__(self, name, number_of_courses):
        Person.__init__(self, name)
        self.number_of_courses = number_of_courses
    def display(self):
        Person.display(self)
        print(self.number_of_courses)
  • class Teacher(Person): — the parent goes in brackets.
  • Person.__init__(self, name) runs the parent's constructor first, so the teacher also gets name, age and address.
  • Teacher defines its own display, which overrides the parent's; inside it, Person.display(self) reuses the parent version and then adds the course count.
t1 = Teacher("Ahmed", 3)
t1.display()
Ahmed
3
class Student(Person):
    def __init__(self, name, gpa):
        super().__init__(name)        # same as Person.__init__(self, name)
        self.gpa = gpa

s = Student("Omar", 3.7)
print(s.name, s.age, s.gpa)
print(isinstance(s, Person), issubclass(Student, Person))
print(Student.__mro__)                # the order Python searches for methods
Omar 25 3.7
True True
(<class '__main__.Student'>, <class '__main__.Person'>, <class 'object'>)
Worth knowing

When does the child need its own __init__? Only if it sets up something extra. If the child has no __init__, the parent's is used as is. If it defines one, that replaces the parent's, so call the parent's first (Person.__init__(self, …) or super().__init__(…)) and then add the new attributes. Another option: leave __init__ alone and add a method such as set_number_of_classes(self, n) to the child.

2.7

Polymorphism

Polymorphism means "many forms": the same method name does the right thing for different types. You write one loop, and each object responds in its own way.

class Animal:
    def speak(self):
        pass

class Cat(Animal):
    def speak(self):
        return "Meow!"

class Dog(Animal):
    def speak(self):
        return "Woof!"
Worth knowing

pass means “do nothing”. It's used when a method must exist but its body isn't known yet: Animal can't know what sound to make, so each subclass fills it in. You'll also see pass in exercise templates as a placeholder where your code goes.

animals = [Cat(), Dog(), Cat()]
for a in animals:
    print(a.speak())
Meow!
Woof!
Meow!

Worth knowing

A second example: a calculate_area method that takes a radius for a circle and a side length for a square, so the same name does a different calculation. Note that, unlike Java, Python can't have two methods with the same name in one class that differ only by argument types: the second definition simply replaces the first.

print(len("hello"), len([1, 2, 3]), len({"a": 1}))   # len works on many types
print(2 + 3, "2" + "3", [2] + [3])                    # + means add, join, or concatenate
5 3 1
5 23 [2, 3]
Duck typing

Python doesn't even need a shared parent class: any object with a speak() method would work in that loop. "If it walks like a duck and quacks like a duck, it's a duck."

t1 is an instance of Teacher. But Teacher itself is an object too — an instance of type. A class that creates classes is called a metaclass, and type is Python's default one. type(type) is type: the chain ends with itself. Section 2.10 and chapter 3 build on this.

2.9

Encapsulation: protected and private

Encapsulation restricts direct access to an object's data, to prevent accidental changes: ideally the data is changed only through the object's own methods. Python signals this with name prefixes:

PrefixMeaningWhat Python actually does
namepublicanyone can read and change it
_nameprotected — "internal, please don't touch from outside"nothing: it's only a convention
__nameprivaterenames it to _ClassName__name (name mangling) so it can't be reached by its plain name from outside
Worth knowing

A company example: anyone may know an employee's name (public). The project they work on should be known to them and the people under them, i.e. the class and its subclasses (protected, _project). The salary should be known only to the employee (private, __salary).

class Employee:
    def __init__(self, name, project, salary):
        self.name = name
        self._project = project
        self.__salary = salary
class subEmplyee(Employee):
    def edit(self, name, project, salary):
        self.name = name
        self._project = project
        print("After modification: ", self.name, self._project)
        Employee.__salary = salary
        print(Employee.__salary)
e1 = Employee("Ahmed", "P2", 12000)
se1 = subEmplyee("Mohmed", "p2", 12344)
se1.edit("DASF", "DASF", 1236575)
After modification:  DASF DASF
1236575
e1._project
'P2'
e1.name
'Ahmed'
e1.__salary
AttributeError: 'Employee' object has no attribute '__salary'

So where did the salary go? Look inside the object:

print(e1.__dict__)
print(e1._Employee__salary)     # the mangled name works: "private" is a strong hint, not a lock
{'name': 'Ahmed', '_project': 'P2', '_Employee__salary': 12000}
12000
Look closely at edit()

It looks as if edit changed the salary to 1236575. It didn't. Inside class subEmplyee, the name __salary is mangled using that class's name, so Employee.__salary = salary actually creates a brand-new class attribute Employee._subEmplyee__salary. The employee's real private salary, _Employee__salary, is untouched:

print(se1._Employee__salary)                          # still the original 12344
print([k for k in vars(Employee) if "salary" in k])   # the accidental new class attribute
12344
['_subEmplyee__salary']

That's encapsulation working as designed: a subclass can't silently rewrite its parent's private data. The proper way is for the class that owns the data to offer a method:

class Employee:
    def __init__(self, name, project, salary):
        self.name = name
        self._project = project
        self.__salary = salary

    def get_salary(self):
        return self.__salary

    def set_salary(self, value):
        if value < 0:
            raise ValueError("salary can't be negative")
        self.__salary = value

e2 = Employee("Salma", "P3", 15000)
e2.set_salary(16000)
print(e2.get_salary())
e2.set_salary(-5)
16000
ValueError: salary can't be negative
Worth knowing

“In Python almost everything is public in the end.” The underscores are an agreed convention that tells anyone reading your code what not to touch. As shown above, the private value is still reachable from outside as object._ClassName__attribute.

2.10

Metaclasses: a first look

The chapter closes with the idea that ties everything together:

  1. A class is a blueprint for an object.
  2. An object is an actual instance of what that blueprint defines.
  3. A metaclass is a class whose instances are classes: it is the blueprint for blueprints. Python's built-in metaclass is type.
Worth knowing

Before chapter 3: make sure this chapter's OOP ideas are solid — classes, inheritance and encapsulation — because metaclasses, decorators and generators build directly on them.

print(type(t1))         # object  -> made by the class Teacher
print(type(Teacher))    # class   -> made by the metaclass type
print(type(type))       # type    -> made by itself
<class '__main__.Teacher'>
<class 'type'>
<class 'type'>

Chapter 3 shows how to build classes with type() directly and how to write your own metaclass.

Summary

  • A class is a blueprint; calling it creates an instance. __init__ sets up each new object; self is that object.
  • Instance attributes (self.x) belong to one object; class attributes are shared. Change shared ones via the class name, or you'll shadow them.
  • hasattr / getattr / setattr reach attributes whose names are only known at run time.
  • Inheritance: class Child(Parent) reuses and overrides; call the parent with Parent.__init__(self, …) or super().__init__(…).
  • Polymorphism: one method name, a different behaviour per type.
  • Encapsulation: _x = protected by convention, __x = private via name mangling (_Class__x). Change private data through the owning class's methods.
  • Everything is an object: instances are made by classes, classes by the metaclass type.
